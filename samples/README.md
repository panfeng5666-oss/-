# 测试样例

这里放的是**系统功能测试的产出**，不是真实项目。

两份样例都来自 `docs/需求来源-GeminiSpark导出.md` 中的测试指令 —— 当时是为了验证 Skill 能否跑通、能否联合调用、符号能否贯穿各模块。**产品是虚构的**。

| 文件 | 测试目的 |
| --- | --- |
| `01-测试-海盐耐候红钢镇纸.md` | 单系统跑通（器物叙事与微内容） |
| `02-测试-海盐冷萃咖啡豆与粗陶随行杯礼盒.md` | 7 系统联调，验证超级符号是否贯穿包装、空间、叙事与话术 |

## 怎么用它们

**该用的**：看**交付结构与颗粒度** —— 一次调用该输出哪几块、每块写到什么程度、模块之间怎么衔接。这是它们唯一的价值。

**不该用的**：里面所有具体数字都是演示值 —— BOM ¥65.00、MSRP ¥218、毛利率 58.2/70.2/76.6%、450g 净重、AQL 与 ΔE 阈值、照度值。**不要在真实项目里引用，也不要当作定价或成本的参照。** 真实项目的定价对标去 `knowledge/09` 的企业案例（老铺黄金、豫园、太湖雪）。

## 真实项目放哪

`cases/` —— 目前是空的。每完成一次真实全案，按 `cases/<编号>-<产品名>.md` 沉淀，并在文件头标注项目背景与调用了哪些系统。
